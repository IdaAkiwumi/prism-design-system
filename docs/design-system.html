PRISM Design System

Tokens, components, themes, and AI agentic patterns – fully themeable via data-theme.

Semantic tokens

PRISM uses semantic tokens to express intent—never raw primitives in component styles. Theme switching updates these tokens so components adapt automatically.

Token Intent Current value Swatch
--color-action-primary Primary CTAs, focused elements #0066CC
--color-surface-default App background, base surfaces #FFFFFF
--color-surface-raised Cards, modals, dropdowns #F5F5F5
--color-text-primary Main body text #111111
--color-text-inverse Text on colored / dark surfaces #FFFFFF
--color-feedback-success Positive confirmations #00AA44
--color-feedback-warning Cautionary states #F4A300
--color-feedback-danger Errors, critical alerts #E50914

Token mapping example

Button → tokens

Primary button background uses var(--color-action-primary) and text uses var(--color-text-inverse) (overridden to #111111 in Education). 

// Primary button (Base & Entertainment)
.btn-primary {
  background: var(--color-action-primary);   // semantic: primary CTA
  color: var(--color-text-inverse);         // semantic: inverse text
}

/* Education theme override: light amber background needs dark text */
[data-theme="education"] .btn-primary {
  color: #111111;
}

Cards inside cards switch to var(--color-surface-default) to maintain hierarchy.

Core components

Each component preview shows visual variants, token mappings, and example code. All styles rely on semantic tokens, so theme switching updates them instantly.

Button

Preview

Primary buttons use --color-action-primary and inverse text. In Education theme, text color is explicitly overridden to #111111 to maintain a 4.5:1 contrast ratio.

Code snippet
<button class="btn btn-primary">Primary</button>
<button class="btn btn-secondary">Secondary</button>
<button class="btn btn-ghost">Ghost</button>
Token mapping
  • Primary: background --color-action-primary, text --color-text-inverse
  • Secondary: border neutral, text --color-text-primary
  • Ghost: transparent background, text --color-text-primary

Card

Raised card
Uses --color-surface-raised and --border-radius-default.

Cards provide a raised surface for grouping content. Nested cards automatically switch to --color-surface-default for clear hierarchy.

Code snippet
.card {
  background: var(--color-surface-raised);   // elevated surface
  border-radius: var(--border-radius-default);
  box-shadow: 0 2px 6px rgba(0,0,0,0.08);
}

/* Nested card inside card */
.card .card {
  background: var(--color-surface-default);  // base surface
}

Input

Helper text using --color-text-primary at reduced opacity.
⚠️ Error message using --color-feedback-danger.
Code snippet
<div class="field">
  <label for="email">Email</label>
  <input id="email" class="input" type="email" />
  <div class="input-helper">We'll never share your email.</div>
</div>

.input {
  background: var(--color-surface-default);
  color: var(--color-text-primary);

Themes

PRISM themes are applied via data-theme on the <html> element. JavaScript updates both the attribute and the CSS variables so components respond instantly without reloading the page.

Base theme
Primary: #0066CC
Surface default: #FFFFFF
Text primary: #111111
Entertainment theme
Primary: #E50914
Surface default: #0A0A0A
Text primary: #FFFFFF
Education theme
Primary: #F4A300
Surface default: #FFFBF2
Text primary: #111111
Theme switching contract

When the theme changes, JavaScript must:

  • 1. Update data-theme on <html>.
  • 2. Redefine all CSS variables with the exact hex values from the theme spec.
  • 3. Ensure components update instantly without page reload.
Implementation snippet
function applyTheme(theme) {
  const root = document.documentElement;
  root.dataset.theme = theme;

  if (theme === 'base') {
    root.style.setProperty('--color-action-primary', '#0066CC');
    root.style.setProperty('--color-surface-default', '#FFFFFF');
    root.style.setProperty('--color-text-primary', '#111111');
    root.style.setProperty('--color-surface-raised', '#F5F5F5');
    root.style.setProperty('--color-text-inverse', '#FFFFFF');
  }
  // ...other themes
}

AI agentic patterns

PRISM includes opinionated patterns for AI intent previews, confidence communication, and escalation flows. Confidence is always visible via text and color, and low confidence paths must expose human handoff.

Intent preview card
Summarize quarterly report
Source: Q2_report.pdf • Scope: 3 pages
Confidence: Medium

The model is moderately confident. Some sections contain ambiguous financial terms that may need human review.

Low confidence escalation
Generate legal summary
Source: Contract_v7.docx
Confidence: Low

Uncertain due to missing data and ambiguous clauses. This output should be reviewed by a legal professional.

Pattern checklist
  • Intent preview: always card + badge + actions.
  • High confidence: success badge (green) + “Approve” primary action.
  • Medium confidence: show both “Approve” and “Edit” actions.
  • Low confidence: danger badge (red) + explanation + “Talk to a person” handoff.
  • Accessibility: confidence label must be visible text, not just color.
